# 可拖动满屏原文与剧本工作区设计

日期：2026-07-22

分支：`docs/resizable-script-workspace-design`

状态：`APPROVED_AND_IMPLEMENTED`

实施状态：`true`

## 1. 背景

当前原文页已经使用左侧章节、中间原文、右侧配置的三栏工作区，但这套满高规则仅由 `source-conversion-layout` 触发。切换到剧本实时生成或正式 Revision 后，页面回到旧的通用 Tab 容器：

- 剧本编辑器仍受旧的 `max-width` 和内容自增高度约束；
- 实时草稿依赖固定 `min-height`，没有继承原文页的视口高度合同；
- 长剧本会继续撑高页面，产生整页纵向滚动；
- 中央内容只占左侧一部分，右侧留下大面积空白；
- 生成中和生成完成使用不同空间结构，状态切换时发生跳位；
- 两块大型锁定提示占用大量首屏高度，重要正文和操作被推到下方。

用户已确认以当前页面的白色工作台、浅蓝状态面、细边框、紧凑工具栏和右侧浅蓝检查器为视觉基线，不引入新的视觉主题。

## 2. 目标

本次设计的目标是：

1. 原文、实时剧本和正式剧本共享同一套满屏三栏骨架；
2. 页面本身不因正文增长而滚动，主要操作在当前视口内可见；
3. 中央正文获得最高空间优先级；
4. 用户可自由调整左右栏宽度，并对所有项目统一生效；
5. 生成前后只改变内容状态，不改变栏位和整体尺寸；
6. 保留现有流式生成、剧本 Skill 校验、Revision 和审批语义。

## 3. 非目标

本次不包含：

- 修改供应商、Worker、SSE 或剧本 Skill 协议；
- 修改剧本生成、校验、Revision 或审批后端语义；
- 新增数据库字段或服务端用户偏好；
- 重新设计全站视觉语言；
- 修改分镜、资产、Shot Prompt、Agnes 或结果工作台；
- 真实 Provider 请求；
- 多用户或跨设备布局同步。

## 4. 已确认产品决策

### 4.1 统一三栏工作台

采用方案 A：

```text
左侧章节导航 | 中央原文或剧本 | 右侧配置、生成状态或校验
```

原文配置、流式生成、生成失败和正式剧本 Revision 均使用相同栏位。状态切换不得改变三栏的顺序、占比或工作区外框。

### 4.2 默认百分比

大屏默认比例：

```text
章节导航 11% | 中央正文 73% | 右侧检查器 16%
```

中等桌面默认比例：

```text
章节导航 14% | 中央正文 66% | 右侧检查器 20%
```

中央正文始终是主要区域。不得再为中央剧本设置旧的固定最大宽度；正文纸张可以控制可读行长，但纸张所在的中央栏必须占满分配到的空间。

### 4.3 用户可拖动

两条栏间分隔线均可拖动。拖动结果使用百分比表达，不保存像素值。

约束：

```text
左栏：8%–20%
右栏：12%–28%
中央栏：不得低于 55%
三栏之和：始终为 100%
```

如果一次拖动会违反任何约束，界面在最近合法比例处停止，不允许出现横向滚动或重叠。

双击任一分隔线恢复当前断点的默认比例。分隔线获得焦点后：

- 左右方向键每次调整 1%；
- `Shift + 左右方向键` 每次调整 5%；
- 调整结果与鼠标拖动遵守同一边界。

### 4.4 所有项目统一

栏宽是本地工作台偏好，而不是项目数据。它对所有项目和章节统一生效，保存在浏览器本地存储：

```text
ai-drama:workspace-pane-ratios:v1
```

保存对象至少包含版本、左栏百分比和右栏百分比。中央百分比由 `100 - left - right` 计算，避免出现三个独立值之和不为 100%。该对象只有一份全局原始偏好，不按项目、章节或路由复制。

读取到格式错误、非有限数值、未知版本或越界值时，必须忽略该值并恢复当前断点默认比例。不得因为本地偏好损坏而阻塞页面。

## 5. 视口与滚动合同

### 5.1 页面高度

桌面端章节工作区占满应用导航下方的剩余动态视口。工作区由以下固定或紧凑区域组成：

```text
章节标题
七阶段轨道
流程门状态栏
三栏工作区（占满剩余高度）
```

不得继续使用 `max(864px, ...)` 强制把页面撑到视口之外。高度应由应用外壳和动态视口计算，并沿父级逐层设置 `min-height: 0`，让内部滚动能够生效。

### 5.2 单一职责滚动

桌面端页面本身不承担长内容滚动。三栏分别管理自己的内容：

- 左栏：章节列表滚动，标题、搜索框和新建章节操作保持可见；
- 中央栏：原文或剧本正文滚动，工具栏与底部状态栏保持可见；
- 右栏：配置、生成详情、校验或版本列表滚动，底部主要操作保持可见。

任何栏的内容增长不得改变相邻栏的高度或宽度。底部操作不得覆盖正文最后一行。

### 5.3 流程门

现有两块大型锁定提示合并为一条紧凑的“流程门”状态栏。默认只显示：

- 当前阻断摘要；
- 下一步解锁条件；
- `查看原因` 操作。

详细原因按需展开，不长期占用首屏高度。

## 6. 三种工作状态

### 6.1 原文配置

左栏继续显示章节导航；中央栏显示原文编辑器；右栏显示文本模型、目标时长、原文版本、就绪校验、结构预览和生成操作。

原文页现有浅蓝检查器风格继续作为右栏视觉基线。右栏较窄时：

- 表格改为摘要列表；
- 次要说明换行；
- 底部按钮允许垂直排列；
- 不通过横向滚动容纳控件。

### 6.2 实时剧本生成

点击 `保存并生成剧本` 后立即进入同一三栏骨架的剧本状态：

- 左栏保留章节导航，并将当前章节标记为 `正在生成`；
- 中央栏逐段追加规范化后的剧本正文；
- 右栏显示当前活动会话真实提供的字数、耗时、连接状态、错误和收尾阶段；不得使用当前项目绑定猜测活动任务的冻结模型。原文配置页继续显示用户实际选择的模型与目标时长；未来只有在活动会话 API 显式返回冻结任务摘要后，剧本生成栏才可展示该摘要；
- 中央栏保持只读，避免用户编辑与流式增量冲突。

用户停留在正文末尾附近时自动跟随；用户主动向上滚动后停止跟随，并提供 `回到生成末尾`。自动跟随只能滚动中央正文容器，不得滚动整个页面。

### 6.3 正式剧本 Revision

Provider 完成、响应可解析且剧本 Skill 校验通过后，才创建正式 Revision。布局不切换：

- 中央栏在原位置显示可编辑的正式剧本；
- 右栏切换为 Revision 历史、Skill 校验摘要和 `确认剧本`；
- 顶部阶段从 `剧本生成` 变为 `剧本待确认`；
- 中央滚动位置尽量保持，不因控件切换回到页面顶部。

## 7. 失败与恢复

生成失败时：

- 中央栏保留已接收的部分草稿；
- 明确标记该内容未保存为正式 Revision；
- 右栏显示稳定错误码、复制部分草稿和返回原文重新生成；
- 不自动重新提交供应商请求；
- 三栏比例和滚动容器保持不变。

刷新页面或切换标签后，现有持久化生成会话继续恢复。恢复过程不得覆盖用户保存的全局栏宽偏好，也不得根据恢复内容重新计算栏宽。

## 8. 响应式规则

### 8.1 大屏桌面

```text
宽度 >= 1440px
默认 11% / 73% / 16%
允许拖动
```

### 8.2 中等桌面

```text
1024px <= 宽度 < 1440px
默认 14% / 66% / 20%
允许拖动
仍强制中央 >= 55%
```

同一份全局原始偏好在进入不同断点时必须重新钳制到该断点的合法范围；不能直接套用导致内容溢出。响应式钳制本身不得覆盖本地存储。只有用户主动拖动或使用键盘调整时才保存新偏好，因此回到大屏后仍能从原始偏好重新计算，而不是继承中等屏幕的临时钳制值。

### 8.3 窄屏

```text
宽度 < 1024px
中央正文占满
章节导航和右侧检查器改为抽屉
关闭拖动分隔线
```

窄屏抽屉不改变工作流语义。主要生成、重试、确认操作仍必须可见且可操作。

## 9. 前端组件边界

现有不一致来自 `ChapterWorkspace`、`SourceTab` 和 `ScriptTab` 使用不同布局合同。实施时应引入一个共享且有限的工作区边界，而不是继续增加页面特定的 `:has(...)` 规则。

建议职责：

### `ResizableChapterWorkspace`

- 渲染三栏 Grid；
- 接收左、中、右三个内容区域；
- 应用断点默认值和合法范围；
- 管理拖动与键盘调整；
- 发布当前比例 CSS variables；
- 不理解原文、剧本或供应商业务。

### `WorkspaceDivider`

- 提供拖动命中区域和视觉分隔线；
- 提供 `role="separator"`、方向、当前值和边界；
- 支持鼠标、指针、键盘和双击恢复；
- 拖动时不得触发布局外的文本选择。

### `WorkspaceRatioPreference`

- 从本地存储读取和校验版本化偏好；
- 保存所有项目统一的百分比；
- 在存储不可用或数据损坏时返回默认值；
- 不发起网络请求。

### 页面内容

- `SourceTab` 提供原文状态的三栏内容；
- `ScriptTab` 提供实时生成、失败或正式 Revision 的三栏内容；
- `ChapterWorkspace` 提供章节标题、阶段轨道和紧凑流程门；
- 现有生成 API、SSE hook、Skill 校验和 Revision mutation 保持不变。

## 10. 可访问性与交互细节

- 分隔线使用 `role="separator"` 和 `aria-orientation="vertical"`；
- 暴露当前百分比、最小值和最大值；
- 键盘焦点必须清晰可见；
- 可点击命中区域应大于视觉分隔线，不要求用户精确点击 1px 边界；
- 拖动光标使用列调整语义；
- 状态不能只依赖颜色，同时显示文字或图标；
- `prefers-reduced-motion` 下不使用装饰性宽度动画；
- 内容和操作的焦点顺序与视觉顺序保持一致；
- 抽屉开启后正确管理焦点，关闭后返回触发控件。

## 11. 测试计划

### 11.1 单元测试

覆盖：

- 默认比例按断点选择；
- 左右拖动转换为百分比；
- 左右边界和中央 `55%` 下限；
- 三栏之和始终为 100%；
- 双击恢复当前断点默认值；
- 方向键 1% 和 `Shift` 5% 调整；
- 全局本地偏好保存与恢复；
- 无效 JSON、未知版本、非有限值和越界值回退；
- 本地存储不可用时页面仍可工作。

### 11.2 组件测试

覆盖：

- 原文、实时生成、失败和正式 Revision 使用同一三栏骨架；
- 点击生成后栏位和比例不改变；
- 生成完成后右栏内容切换但尺寸不改变；
- 用户向上滚动时停止自动跟随；
- `回到生成末尾` 只滚动中央容器；
- 流程门默认紧凑并可展开原因；
- 窄屏不渲染可拖动分隔线，改用抽屉；
- 现有生成、重试、保存和确认操作继续可用。

### 11.3 Playwright 视觉与布局验收

至少验证：

```text
1920 x 1080
1440 x 900
1180 x 800
768 x 1024
```

每个桌面视口分别截图原文、实时生成、部分失败和正式 Revision。断言：

- `document.documentElement.scrollWidth <= window.innerWidth`；
- 桌面工作区不需要滚动网页寻找底部主要操作；
- 三栏不重叠，不出现不可解释的空白列；
- 中央剧本未被裁切且占据最高空间优先级；
- 左、中、右内部滚动互不影响；
- 底部操作不会覆盖正文；
- 拖动后比例立即反映，并在切换项目和刷新后恢复；
- 生成前后没有显著布局跳动；
- 768px 视口使用抽屉且无页面横向滚动。

### 11.4 回归

运行 Web 单元测试、构建和端到端测试。默认测试使用现有 fake provider 或持久化 fixture，不发送真实 Provider 请求。

## 12. 验收标准

只有同时满足以下条件，实施才可验收：

1. 原文、流式剧本和正式剧本共享同一满屏三栏工作区；
2. 大屏默认比例为 `11% / 73% / 16%`；
3. 两条分隔线可拖动，中央栏始终不少于 `55%`；
4. 拖动比例对所有项目统一，并在刷新后恢复；
5. 双击恢复默认比例，键盘可完成同等调整；
6. 页面无横向溢出，桌面端无需滚动网页查找主要操作；
7. 三栏内容使用各自内部滚动；
8. 两块大型锁定提示已压缩为紧凑流程门；
9. 生成中、失败和完成状态不会改变栏位或整体比例；
10. 低于 1024px 时两侧使用抽屉；
11. 现有流式生成、Skill 校验、Revision、审批和错误恢复行为不回归；
12. 自动化测试不发送真实 Provider 请求。

## 13. 回滚

本改动为纯前端布局增量。回滚时恢复原有 `SourceTab` 和 `ScriptTab` 容器及 CSS，不需要数据库迁移或数据修复。本地存储中的版本化比例键可保留并被旧版本忽略；若未来合同不兼容，升级键版本而不是复用旧数据。
