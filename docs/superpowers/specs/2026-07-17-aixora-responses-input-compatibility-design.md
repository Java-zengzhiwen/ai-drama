# AIXORA Responses Input Compatibility Design

Date: 2026-07-17

Branch: `feat/aixora-adapter-model-archive`

Status: `APPROVED`

## Problem

AIXORA accepts `gpt-5.6-sol` with the current string `input`, but a real `gpt-5.6-luna` request can return a completed Responses object containing only a `reasoning` item. AI Drama then correctly reports `PROVIDER_RESPONSE_MALFORMED` because no assistant output exists. The same Luna request with canonical Responses input

```json
[
  {
    "type": "message",
    "role": "user",
    "content": [{"type": "input_text", "text": "..."}]
  }
]
```

returns a completed `message` containing `output_text`, including with `reasoning.effort=high`.

The image failure observed before the AIXORA platform adjustment was upstream state. A post-adjustment AI Drama model test completed, persisted an 816,231-byte PNG, and served it through the local content endpoint with HTTP 200.

## Decision

Adopt option A: when `payload.request.messages` is absent, the AIXORA adapter converts the plain prompt into one canonical Responses `message` with one `input_text` content item. A non-empty caller-supplied `messages` array remains unchanged.

This applies consistently to every AIXORA text model. There is no Luna-only branch and no automatic retry, so one logical model test still creates exactly one paid Provider request.

## Data Flow

```text
plain prompt
→ [{type: message, role: user, content: [{type: input_text, text: prompt}]}]
→ POST /v1/responses
→ responseText reads output[*].content[*].text
→ normalized output and usage
```

Existing `messages` input continues directly to `/v1/responses` without rewriting.

## Error Handling

- A completed response without any text remains `PROVIDER_RESPONSE_MALFORMED`; reasoning summaries are not treated as assistant output.
- HTTP status mapping remains owned by the Worker.
- No fallback request is submitted after an empty response.
- Credential, Authorization header, raw response, signed URL, and generated bytes remain outside Git and logs.

## Verification

1. Red/green adapter tests prove plain prompts use canonical message input and explicit `messages` remain unchanged.
2. Existing AIXORA adapter, compiler, Worker, model-test, and semantic verifier suites remain green.
3. The updated source is saved through the loopback supplier API with ETag protection; the existing credential and model overlays are preserved.
4. Explicitly authorized real acceptance performs exactly one request each for:
   - `gpt-5.6-luna` with `high`;
   - `gpt-5.6-sol` with `high`;
   - `gpt-image-2` text-to-image.
5. Image acceptance requires completed status, valid local image bytes, and HTTP 200 from the model-test content endpoint.

## Rollback

Switch the AIXORA supplier current version back to the previous immutable supplier version. Do not delete model revisions, credential versions, snapshots, or test history.
