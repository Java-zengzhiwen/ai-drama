# 页面与功能覆盖

## 1. 判定规则

每项使用以下事实状态之一：

```text
已完整设计
部分设计
仅出现导航
仅有概念
明确延后
未覆盖
```

“有原型”指 M1–M3 静态 HTML 中有对应可见表面，不表示业务请求真实执行。“有 QA”指该表面在 M2/M3 静态原型 Design QA 中被覆盖；M1 无独立 QA。核心 UI 基线仅为 M1–M3；M4/M6D 只作为相邻继承与扩展证据单独标注。

## 4. 生产实现证据边界

生产实现证据：仓库中存在与相关阶段对应的生产路由、组件、测试和历史里程碑记录。本次仅进行只读证据检查，未重跑生产验收，因此不将其重新判定为当前已验证完成。

下表严格区分核心 UI 基线与相邻继承证据，也不把生产文件存在等同于当前生产实现已重新验证：

| 范围 | 当前仓库证据 | 本次判定 |
| --- | --- | --- |
| 核心 M1 | `/projects`、项目详情、章节工作台路由；Source/Script/Storyboard 组件；M1 E2E | 存在生产实现证据；本次未重新验证 |
| 核心 M2 | ProfilesAssets、AssetGrid、Requirements、ShotPrompt 组件；M2 E2E | 存在生产实现证据；本次未重新验证，也未做源图对比 |
| 核心 M3 | AgnesGeneration、GenerationResults、Rerun Drawer 组件和单元测试；M3 baseline summary | 存在生产实现和历史验证证据；本次未重新验证 |
| 相邻 M4 | RehearsalVisibilityPanel 组件/测试；M4 closeout | 存在工程可见性实现证据；不属于 M1–M3 核心设计包，不等同连续性审核，本次未重新验证 |
| 相邻 M6D | Supplier 页面、项目绑定页面、三视口实现截图和 Design QA | 存在生产实现证据及独立 Product Design QA；不等同多 Provider 生成中心，本次未重新验证 |

因此，“M1–M3 静态原型已验证”不能单独证明生产实现。代码、测试和历史里程碑只构成生产实现证据；只有当前重新执行的生产验证才能支持“当前生产实现已重新验证”。
