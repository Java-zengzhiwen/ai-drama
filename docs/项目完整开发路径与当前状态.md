# 一、项目最终目标

构建一套本地可运行、可追溯、可审批、可扩展的 AI 真人短剧生产系统。

最终完整流程：

```text
小说原文
  ↓
剧本改编
  ↓
人物 / 场景 / 道具设定
  ↓
视觉资产
  ↓
分镜设计
  ↓
逐镜生成提示词
  ↓
LibTV / Agnes 执行
  ↓
视频质检
  ↓
问题镜头重跑
  ↓
最终成片
```

系统核心原则：

```text
Skill 负责专业创作逻辑
Runtime 负责执行
Workflow 负责流程状态
Validator 负责质量检查
Approval 负责人工确认
Artifact / Revision 负责版本管理
Adapter 负责连接 LibTV、Agnes 等平台
```

# 四、当前已经能做什么

当前系统已经可以完整执行：

```text
1. 读取小说原文
2. 读取世界观
3. 读取人物设定
4. 读取制作约束
5. 加载 Script Skill
6. 调用 Mock 或真实模型
7. 生成 Markdown 剧本
8. 保存 Run
9. 保存 Artifact
10. 保存 Revision
11. 执行 Validator
12. 查看生成结果
13. 对比两个 Revision
14. 人工 Approve / Reject
15. 导出 Approved Script
16. 生成 Provenance
```

当前已形成的正式链路：

```text
小说输入
  ↓
Script Skill
  ↓
真实模型
  ↓
剧本 Revision
  ↓
Validator
  ↓
人工审批
  ↓
导出正式剧本
```

# 九、Storyboard Workflow MVP 完成标准

只有以下全部完成，Storyboard 阶段才算通过：

- [ ] Storyboard Skill 有正式 Manifest
- [ ] Storyboard Skill 有 Package Hash
- [ ] 输入必须是 Approved Script Revision
- [ ] 未批准 Script 禁止运行
- [ ] Storyboard Run 在模型调用前保存
- [ ] Storyboard Revision 不可变
- [ ] 记录来源 Script Revision
- [ ] Storyboard Validator 已登记
- [ ] Required Validator Failure 阻止审批
- [ ] Storyboard Approval 历史追加保存
- [ ] 当前批准版本唯一
- [ ] Script Approved Revision 变化后，旧 Storyboard 标记 stale
- [ ] Storyboard Compare 可用
- [ ] Storyboard Export 可用
- [ ] 重启后恢复
- [ ] Mock 测试通过
- [ ] 真实模型测试通过
- [ ] 现有 47 个 Script Runtime 测试继续通过
- [ ] 新增 Storyboard 测试全部通过
- [ ] Migration Verification 继续通过
- [ ] Working Tree Clean
- [ ] 不直接在 main 开发

# 十、分支开发规则

稳定分支：

```text
main
```

新功能开发：

```bash
git checkout main
git checkout -b feat/<功能名称>
```

合并前必须满足：

```text
完整 pytest 通过
migration verify 通过
CLI 回归通过
真实模型测试通过
独立审阅通过
working tree clean
```

禁止：

- [ ] 直接在 `main` 开发大功能
- [ ] 覆盖旧 Artifact Revision
- [ ] 静默复用 stale 下游结果
- [ ] 测试失败时合并
- [ ] 提交 API Key
- [ ] 提交 `.env.local`
- [ ] 将 Agnes / LibTV 写进 Runtime 核心
